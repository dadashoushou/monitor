抓取模式（crawl_mode）功能的视觉方案 — auto / html / js / stealth

1 / 模式配色方案

四种抓取模式各有独立色系。auto 使用中性灰（默认态，不抢视觉），html 沿用蓝色系（与现有"检测中"一致，表示静态可靠），js 使用紫色（表示动态渲染的复杂度），stealth 使用橙色（表示高级/隐蔽操作）。

2 / Badge 设计规范

模式 badge 在现有 pill badge 基础上增加左侧圆点指示器，与 RSS 状态 badge 形成视觉区分。状态 badge 保持原样不变。

模式 badge AUTO HTML JS STEALTH
状态 badge RSS 无RSS 待检测
设计决策：模式 badge 带圆点前缀，状态 badge 不带。两类 badge 在同一行出现时可快速区分语义。
3 / 四种模式说明
AUTO 自动模式
默认模式。有 RSS 时走 RSS 抓取，无 RSS 时回退到 HTML 静态抓取。兼容现有所有站点，无需手动配置。
crawl_rss() → crawl_html() fallback
HTML 静态抓取
使用 Scrapling Fetcher 抓取静态 HTML 页面。适用于服务端渲染的传统网站，速度快、资源消耗低。
Fetcher.get() · 5 并发
JS 动态渲染
使用 Scrapling DynamicFetcher 启动无头浏览器渲染 JavaScript。适用于 SPA 或重度 JS 渲染的站点。
DynamicFetcher.fetch() · 2 并发
STEALTH 隐蔽抓取
使用 Scrapling StealthyFetcher，具备反检测能力。适用于有 bot 防护的站点，资源消耗最高。
StealthyFetcher.fetch() · 2 并发

8 / 数据流变更概览

crawl_mode 字段从前端表单 → API → sites.json → crawler 路由的完整流转。

前端 select → POST /api/sites → sites.jsoncrawl_mode: "js" → crawl_site() → DynamicFetcher
向后兼容：已有站点无 crawl_mode 字段时，读取默认为 "auto"，无需迁移数据。
9 / 实施清单
# 文件 变更内容 优先级
1 crawler.py 新增 _extract_articles()、crawl_js()、crawl_stealth()；重写 crawl_html() 用 Scrapling；修改 crawl_site() 路由和 crawl_all() 并发策略 P0
2 app.py add_site() 和 update_site() 接收并存储 crawl_mode 字段，默认 "auto" P1
3 templates/index.html 弹窗增加模式选择器、表格增加模式列、新增 badge 样式、STATUS_LABEL 映射 P1
4 sites.json 无需迁移，读取时缺失字段默认 "auto" P2
